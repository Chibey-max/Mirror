# 0003 — CopyVault lifecycle review decisions

Date: 21 September 2026. Owner: Jason. Applies to PR #14 and amends PRD v2.2 §7.7.

- At most **50 active followers per agent**, including zero-cap follows. `MAX_FOLLOWERS_PER_AGENT()` exposes the limit. `FollowerLimitReached(uint256 agentId)` rejects the next follow before state changes or policy calls. Unfollow releases a slot. This bounds list size but does not prevent someone occupying all slots. Measured with isolated test setup and 50 funded followers, a buy using the PRD's 0.42 mNVDA at $128.41 example costs **3,137,690 gas** (about 10.5% of a 30M block), while a sell costs **831,008 gas**. The V1 capacity therefore still fits with substantial headroom.
- A new follow requires a registered, active agent from TrackRecord's registry. Unknown and inactive agents revert `AgentNotFound(uint256 agentId)` and `AgentInactive(uint256 agentId)`. Unfollow never checks agent activity, so deactivation cannot block exit. Validation order is AlreadyFollowing, InsufficientBalance, follower limit, agent existence, agent activity.
- Every successful follow saves the current global `TrackRecord.fillCount()`. Only fills with strictly greater IDs are eligible for that follow. Re-follow captures a new boundary; unfollow clears it. IDs distinguish transactions even within the same block timestamp. Mirroring skips ineligible followers and marks a successfully processed fill as mirrored even when none were eligible.
- Constructor code checks now use `ZeroTrackRecord()`, `ZeroPolicyModule()`, and `ZeroUsdg()`. These errors cover both zero and nonzero code-less addresses. They do not prove the dependency has the intended code or wiring.
- `isMirrored` is the replay guard's public read. `mirrorFill` is runner-only, processes a fill once, and catches each follower's PolicyModule rejection as `MirrorRejected`.
- CopyVault supports only 18-decimal Stock Tokens and checks `decimals()` once per fill before notional calculation. Missing, malformed or non-18-decimal metadata reverts `InvalidTokenDecimals(address token)`. This prevents an allowlisted lower-decimal token from making the daily cap ineffective.
- `InvalidTokenDecimals` and `NotionalOverflow` describe a malformed fill, not an individual follower's policy rejection. Both revert before the fill is marked mirrored. The runner must treat either error as final for that fill, stop retrying it and alert an operator; retrying the same call cannot change the result. Runner code is not yet present in this repository, so this is an integration requirement rather than an implemented retry policy.
- Zero-amount deposits/withdrawals and zero-cap follows remain permitted. Position epochs clear positions in constant time on unfollow. Same-day policy spend must survive re-follow.
- The three withdrawal acceptance tests now run in their original required-test file. Their allocation case uses the policy double until real policy integration is available.
- PR #15's PolicyModule interface and implementation landed before the mirroring work. The integrated vault tests exercise real cap rejection, idempotent kill and same-day spend retention; no PolicyModule ABI changes are included here.
- CI pins Foundry v1.7.1, matching the local formatter/compiler driver. All contributors should use the same release. The Solidity compiler remains pinned by foundry.toml.

The frontend CopyVault ABI includes the added constructor/admission errors, `InvalidTokenDecimals`, and the capacity getter. No existing function or event signature changes. These additive ABI changes must be included in the team's PRD amendment review.
